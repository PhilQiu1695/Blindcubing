What is a valid memo?
1. Start at buffer position: edges start from the UF top (U face) sticker, corners start from the UFL top (U face) sticker.
2. Note the sticker in this position and record sticker letter 
#position letter: what the letter on the face would be for a solved cube. 
#sticker letter: the actual letter on the face in the scramble)
3. Go to the position the letter is supposed to be
4. Repeat steps 2-3 until hit buffer sticker
5. For pieces in right place but wrong orientation (flipped edge / twisted corner): treat each one as a small cycle (steps 8-9), giving 2 lowercase letters. Put these blocks at the end of their section, each in its own brackets.
#The 2 letters show the direction: e.g. UBR twisted clockwise reads gh, counter-clockwise reads gi.
#Example corner memo: Corners MP RK dZ e (gh) (lowercase d and e mark a small cycle, (gh) is the UBR corner twisted clockwise in place)
6. If no unrecorded pieces (edges or corners): FINISH
7. For unrecorded: exist small cycles
8. start at arbitrary unrecorded piece, record the position letter in lowercase, not the sticker letter.
9. steps 2, 3 repeat until hit the letter recorded in step 8 (or another sticker of that piece), and record that closing letter in lowercase
#Small cycle rule: the start and closing letters are always written, both lowercase. They may be different stickers, as long as both are on the same piece (e.g. dZ e: d and e are both on the UBL corner).
#Buffer in place: if the buffer piece is already in the buffer slot (solved, flipped or twisted) while other pieces are unsolved, skip step 2-4 and start a small cycle (step 8) straight away.

A standard edge memo should have 11 letters(corner 7), add one for each small cycle, and subtract one for each piece in its right position
When starting to record cycles for corners, have the first position letter be the one on the top/bottom face of the cube i.e. blue/green

Parity: no separate notation. It is implied by the letter count: an odd number of letters (brackets included) means parity. Edge and corner counts are always both odd or both even; a mismatch means the memo is wrong.

Memo format: letters in pairs separated by single spaces (e.g. MP RK dZ e), with in-place blocks last in brackets. This format is for the player only: the checker ignores case, brackets and spaces (e.g. mqgjzers is accepted for MQ GJ ZE (rs)).

Results: 2 strings for edge + corner

Workflow:
Current stage: Steps 1-8 built (data structures, move engine + parser, reference cross-check, memo spec, memo checker and cycle tracer in memo.py, net visualizer in visual.py, CLI trainer in trainer.py). Next: Step 8's manual check (5 real training sessions), then Additional functions.

1. **Define Data Structures & Letter Scheme Mappings:** Prerequisite for all tracing logic. [DONE]
Build the foundational cube state class and static lookup dictionaries for the JB method.

* **Implementation:**
* Create `Cube3BLD` initialized with 12 edge slots `[(0, 0) ... (11, 0)]` and 8 corner slots `[(0, 0) ... (7, 0)]`. Each slot holds `(piece_id, ori)`; piece_id is the piece's home slot.
* Set up static dictionaries mapping every slot index and face orientation to its corresponding JB letter (e.g., `Edge Slot 6` on `R` face $\rightarrow$ `'Z'`, `B` face $\rightarrow$ `'Y'`).
* Define constants for the buffers: Edge Buffer = `UF` (Slot 2), Corner Buffer = `UFL` (Slot 3). Buffer stickers get placeholder labels (`#U`, `#F`, `#L`) so any sticker can be read, even when the buffer piece has moved.
* Orientation convention: the sticker on a slot's face i is the piece's sticker (i + ori) mod n, using the slot face orders.
* Corner slot face orders all start with the U/D face and go clockwise around the corner (e.g. UFR = (U,F,R), UFL = (U,L,F)). Mixing handedness makes some states impossible to represent.


* **Verification Check:**
* Write a unit test that iterates through all 22 non-buffer edge stickers and 21 non-buffer corner stickers on a solved cube state.
* Verify that every slot returns its exact letter as defined in your design doc lookup table.




2. **Implement Move Engine & Scramble Parser:** Ensures state tracking accuracy. [DONE]
Implement quarter-turn metric move mechanics and string scramble application.

* **Implementation:**
* Build `apply_move(move_str)` supporting standard outer-layer moves (`U`, `D`, `L`, `R`, `F`, `B` and modifiers `'`, `2`). Parse strictly: reject `R2'`, `r`, `Rw`, etc.
* Each base move is a clockwise quarter turn (as seen looking at that face). Edges flip according to the per-move table; corners update as `ori = (ori + twist) mod 3`, with twist 0 for U/D and alternating 1, 2 around the cycle for R/L/F/B.
* Add `scramble(scramble_str)` to execute a space-separated sequence of moves.


* **Verification Check:**
* Apply 6 repetitions of `R U R' U'` (sexy move) and assert that `cube.edges` and `cube.corners` return to their exact starting solved tuples `(slot, 0)`.
* Apply `R` once and check that corners 1, 2, 5, 6 update their slot positions and orientation offsets accurately.
* Check sticker letters against a physical cube after single turns (e.g. after `R`, UFR's U face shows `Y`). "N turns = solved" tests alone can't catch a wrong turn direction or twist convention.




3. **Cross-check Against an Independent Sticker Model:** Proves the move engine is correct. [DONE]
A move engine can pass every self-consistency test and still be wrong (this happened: U/D were reversed and corner twists were wrong).

* **Implementation:**
* In `tests.py`, build a separate 3D sticker simulator: each sticker is a (position, normal) vector, and a face turn rotates every sticker in that layer by 90 degrees.


* **Verification Check:**
* Every face turn and modifier, plus 500 seeded random scrambles, give identical sticker letters in both models.




4. **Decide the Memo Spec:** Steps 5-8 all depend on these rules. [DONE]
Write down exactly what a valid memo string looks like before building the checker.

* **Decided:**
* Buffer start: edges from the UF top (U face) sticker, corners from the UFL top (U face) sticker.
* Small cycles: the start and closing letters are always written in lowercase. They may be different stickers of the same piece (see "What is a valid memo?" step 9).
* Buffer piece already in the buffer slot (solved, flipped or twisted): start a small cycle straight away.
* Flipped edges / twisted corners in place: written as a 2-letter small cycle, in brackets, at the end of the section (e.g. clockwise UBR = (gh)).
* Format: letter pairs separated by single spaces; bracket blocks last. The checker ignores case, brackets and spaces.
* Parity: no notation; implied by an odd letter count. Edge and corner counts must have the same parity.
* Scramble orientation: scramble in the WCA hold (white top, green front) and memo in green top / red front. Translate moves U->R, F->U, R->F, D->L, B->D, L->B.


* **Verification Check:**
* Hand-write the memo for 3-5 scrambles, including one with parity and one with a twisted corner, using only the written rules.




5. **Implement Memo Executor & Checker:** Enables flexible user checking. Built before the tracer so it can verify the tracer. [DONE - memo.py]
Validate user-submitted memo strings by simulating them on the scrambled cube.

* **Implementation:**
* **Executor (main check):** Each letter means "swap the buffer sticker with this target sticker". Apply the user's memo letters as swaps on a copy of the scrambled cube, apply the parity rule, and check that the cube is solved. This accepts any valid memo.
* **Reference memo (display only):** Show the tracer's memo (Step 6) next to the user's. Don't use it for pass/fail.
* Parity flag detection: an odd number of edge targets means parity. The corner count must also be odd, otherwise the memo is wrong.


* **Verification Check:**
* Input an alternate valid cycle break for a scramble with floating cycles (e.g., breaking to piece `A` vs piece `C`) and confirm the simulator accepts both as valid solutions.
* Input intentionally flawed memos (e.g., missed flipped edge or twisted corner) and ensure the engine marks them incorrect.




6. **Develop Cycle Tracing Engine:** Core algorithmic challenge. [DONE - memo.trace_memo]
Implement blindfolded cycle tracing logic for edges and corners using JB rules.

* **Implementation:**
* **Main Loop:** Read the piece in the buffer slot. If it is not the buffer piece, append target letter to memo and jump to that target's slot.
* **Cycle Breaks:** When returning to the buffer while unsolved pieces remain, break into the unrecorded piece with the lowest start letter (alphabetical) as a new cycle break.
* **Rule Enforcement:** For corners, always break cycles using the top/bottom (`U`/`D` face) sticker first.
* **In-place Flips/Twists:** Handle them with the notation decided in Step 4.


* **Verification Check:**
* Property test: for 1000+ random scrambles, feeding the tracer's memo to the Step 5 executor solves the cube.
* Test against known simple scrambles:
* Single swap target (e.g., `R2` or `U2`).
* Buffer piece in place: solved, flipped (edge) and twisted (corner), each with other pieces unsolved.
* Small cycles whose closing letter is a different sticker of the start piece.
* Known benchmark scrambles from the Bilibili tutorial.
* Verify generated edge memo string length and corner memo string length match hand-traced expectations.




7. **Build 2D Net Visualizer:** Display tool for users (no longer the main debugging tool; Step 3 covers correctness). [DONE - visual.py]
Convert internal piece orientation states into face sticker colors/letters and render a 2D unfolded cube net.

* **Implementation:**
* Implement `get_face_grid(face)` to query edge/corner sticker values for all 6 faces (`U`, `L`, `F`, `R`, `B`, `D`).
* Build `print_cube_state(mode)` supporting face-letter mode (`U`, `F`, `R`...), JB-letter mode (`E`, `G`, `J`...) and colour mode (`G`, `R`, `W`...) for comparing with a physical cube.


* **Verification Check:**
* Apply a short test scramble (e.g., `R U`).
* Print the 2D net and compare it against a physical cube or 3D visualizer in **Green Top / Red Front** orientation to confirm sticker placement match.




8. **Build CLI Trainer Interface:** Final integration step. [BUILT - trainer.py, run with python3 trainer.py; manual 5-session check pending]
Create the interactive command-line app loop for end-user practice.

* **Implementation:**
* Implement a random-move scramble generator (20-25 moves). Block a repeated face (`R R`) and same-axis triples (`R L R`). (WCA scrambles are random-state; random-move is fine for training.)
* Show scrambles in the WCA hold and translate them to the memo hold before applying (Step 4).
* Create the user loop:
1. Display scramble string.
2. Prompt for Edge Memo input.
3. Prompt for Corner Memo input.
4. Run validation engine and output results (Success / Fail + Correct Reference Memo + Optional 2D net diagram).




* **Verification Check:**
* Run 5 complete training sessions. Confirm smooth execution, accurate score reporting, and clean handling of empty or formatted inputs (e.g., space-separated letter pairs).
